# 新幹線の旅程づくり

カレンダーの予定から会場と時刻を調べ、新幹線＋在来線・バスの行き帰りを組んで提案する。予約はユーザーがする。

## 大原則

- **予約・ログイン・支払いはしない。** 本人のアカウントとカードが要るうえ、発売前のことも多い。買い方と締切を示すところまでやる。
- **時刻は、実際の日付で乗換案内を引いたものだけ書く。** 記憶や一般論の時刻は書かない。
- **乗り継ぎは「急がない・待ちすぎない」を目指す。** これがユーザーの一番の関心。
- 新幹線の予定はユーザーが自分で入れる。こちらがカレンダーに入れるのは在来線・バス・タクシーの区間だけ。

## 1. 予定を調べる

1. Googleカレンダーで予定を探す。`search_events`（人名＋「結婚式」など）と、その日の `list_events`（`timeZone: Asia/Tokyo`）を両方使う。
2. 場所が空なら、説明欄のリンク（Web招待状など）を開く。招待状はJavaScriptで描画されるので、WebFetchではなくブラウザで開き、スナップショットから読む。
3. 次を書き出す。
   - 会場名・住所・フロア
   - **受付開始の時刻**と、本編の開始・終了の時刻（別物なので分けて読む）
   - 二次会の有無・時刻・場所
   - 出欠の回答期限（あれば最後に一言添える）
4. 会場の公式サイトの「電車・バスでお越しの方」を読む。最寄り駅、バスの乗り場番号・系統・降りるバス停・所要時間、タクシーの所要時間を控える。

## 2. 足りない条件を聞く

AskUserQuestion で、分からないものだけ聞く。

- 新幹線に乗る駅。既定は品川。違いそうなときだけ聞く。
- 帰り方：本編のあと当日帰る／二次会のあと当日帰る／泊まる。泊まるなら shinkansen-hotel-package-search を案内する。
- 着きたい時刻に希望があるか。なければ「受付開始の15〜30分前に会場着」を目標にする。

## 3. 乗換案内で時刻を引く

Yahoo!乗換案内をブラウザで開く。URLで条件を渡せる。

```
https://transit.yahoo.co.jp/search/result?from={出発地}&to={目的地}&y=YYYY&m=MM&d=DD&hh=HH&m1={分の十の位}&m2={分の一の位}&type={1=出発時刻 / 4=到着時刻}&ticket=ic&expkind=1&userpass=1&ws=3&s=0&al=1&shin=1&ex=1&hb=1&lb=1&sr=1
```

- `from` と `to` はURLエンコードする。バス停名もそのまま使える（例：長良川国際会議場前）。
- 目的地がバス停のときは `lb=1`（路線バス）を外さない。外すと結果が出ず、トップに戻される。
- 鉄道だけの区間は `al=0&hb=0&lb=0` にすると、飛行機や高速バスの変な候補が消える。
- 結果は次のJavaScriptで抜き出す。バスの「注記」（工事で運行変更など）は大事なので消さない。

```js
() => [...document.querySelectorAll('[id^="route0"]')]
  .map(e => e.innerText.replace(/\n{2,}/g, '\n').slice(0, 900))
  .join('\n=====\n')
```

### 行き

1. 到着時刻指定（`type=4`）で、会場の最寄りバス停・駅に「受付開始時刻」着で引く。候補が3つ出る。
2. 次の基準で1つ選ぶ。
   - 会場着が受付開始の15〜30分前。
   - 新幹線→在来線の乗り換えが10〜15分。名古屋は新幹線ホーム（14〜17番線）と在来線ホームが離れているので、10分未満は避ける。20分を超えると待ちすぎ。
   - バスへの乗り換えも5〜10分あるもの。
   - **1本遅い候補でも受付に間に合うこと。** それを「予備」として一緒に書く。

### 帰り

1. 出発時刻指定（`type=1`）で引く。出発は「終了時刻＋20〜30分」（お見送り・クローク・荷物の受け取りの分）。
2. 夕方はバスが減る。会場近くの別のバス停（「〜北口」など）も引き、タクシーの所要時間も書く。
3. 在来線は、始発駅から出る列車があれば優先する。引出物などの荷物があっても座れる。
4. 新幹線は、**在来線の2〜3本のどれに乗っても間に合う列車**を選ぶ（乗り換え15〜30分）。スマートEXなら、早く着いたときに当日その場で前の列車へ変えられる。
5. 乗換案内の3候補だけでは足りないときは、名古屋など乗り換え駅→出発駅の区間を、少しずつ時刻をずらして引き直す。

## 4. 切符の買い方をまとめる

東海道・山陽新幹線はスマートEXを前提にする。料金は変わるので、使う前にリンク先で確かめる。

- **発売日**：乗車日の1か月前の10:00。日付と曜日を計算して書く。
- **スマートEX（通常）**：1年前から申し込める。座席は1か月前以降に決まり、メールで届く。当日も何度でも列車を変えられる。東京・品川〜名古屋は11,100円（通常期、[発売額](https://smart-ex.jp/product/plan/service/pdf/service_fares_reserved.pdf)）。
- **EX早特21**：1か月前10:00〜21日前23:30に予約する。のぞみの普通車指定席。**予約後は列車を変えられない。** 品川〜名古屋は10,370円（2026年3月13日乗車分から、[料金表](https://smart-ex.jp/product/hayatoku21/pdf/hayatoku21_fares_from_260313.pdf)）。
- おすすめの組み合わせ：**行きはEX早特21**（時刻が決まっている）、**帰りはスマートEX（通常）**（終わる時刻がずれても変えられる）。
- 在来線は交通系ICで乗る。新幹線を降りたら改札を出ずに、新幹線→在来線の乗り換え改札を通る。
- 乗換案内に出る料金は「通常のきっぷ・自由席」なので、切符の料金には使わない。在来線とバスの運賃だけ使う。
- 東海道・山陽以外の新幹線（東北・北陸など）は、えきねっとの条件を調べ直す。

## 5. チャットで提案する

平易な日本語で、次の順に書く。表は使わない。

```
（一行目）予約はまだしていない理由（発売日・ログインと支払いが要る）

## 予定（どこで確認したか）
- 会場・住所
- 受付・開始・終了の時刻
- 出欠の回答期限（あれば）

## 行き（おすすめ）
1. 新幹線：{駅} {時刻}発 {列車名}（{番線}）→ {駅} {時刻}着
2. 在来線：…（乗り換え{N}分）
3. バス：{乗り場} {時刻}発 {系統} → {バス停} {時刻}着、徒歩{N}分
4. 会場着 {時刻}（受付開始の{N}分前）
予備：1本遅い場合の流れ

## 帰り（おすすめ）
（同じ形。在来線の別の候補も書く）

## 買い方と料金（片道・大人1人）

## 注意
- ダイヤは今のもの。予約のときに同じ列車があるか確かめる
- バスの工事などの注記
- 前提にしたこと（二次会に出ない、など）
```

- 最後に「在来線・バスの予定をカレンダーに入れましょうか」と聞く。
- Sources（使ったページのURL）を並べる。

## 6. カレンダーに登録する

ユーザーがOKしたら、在来線・バス・タクシーの区間を**1区間1件**で作る。新幹線は入れない。

- タイトル
  - `在来線 {乗る駅}→{降りる駅}（{種別} {行き先}行）`
  - `バス {乗り場のある駅}→{会場}（{会社} {系統}）`
  - `移動 {会場}→{駅}（タクシー or バス）`
- 場所：乗る駅、またはのりば（例：JR岐阜バスターミナル 10番のりば）
- 説明
  - 発着時刻・番線・運賃
  - 前後の新幹線と、乗り換え時間
  - 乗り遅れたときの次の便
  - 注意（工事での運行変更、受付の場所など）
- `timeZone: Asia/Tokyo`。通知はカレンダーの初期設定のまま。
- 登録したら、件数と時刻を短く返す。続けて、新幹線はどの列車の時刻で入れればよいかを書く。「違う列車を予約したら教えてください。在来線の予定も合わせて直します」と添える。

## 確認リスト（間違えやすい点）

- カレンダーの名前と招待状の名前が違うことがある（結婚で姓が変わる、など）。招待状の本文で本人か確かめる。
- 「受付開始」と「開始」を取り違えない。到着の目標は受付開始が基準。
- 曜日を計算で確かめ、招待状の曜日と合わせる。
- 臨時列車は運転日が限られる。予約開始日に、その日も走るか確かめるよう書く。
- バスの注記（「工事による運行変更」など）は、そのまま注意に書く。
- 夕方はバスが少ない。タクシーを代わりの手段として必ず書く。
- 帰りにEX早特21を勧めない（変更できないため、終わる時刻がずれると困る）。

## やらないこと

- 予約・ログイン・支払い、個人情報の入力。
- 乗換案内で確かめていない時刻や、公式ページで確かめていない料金を書くこと。
- 頼まれていない新幹線の予定をカレンダーに入れること。
